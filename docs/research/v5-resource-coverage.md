# Lemon Squeezy v5 资源与 operation 覆盖调查

研究截止：2026-08-12（Asia/Shanghai）

## 结论摘要

当前官方 API 导航公开：

- 20 个使用 Bearer credential 的 Authenticated JSON:API resources，共 57 个 operation；
- 1 个独立 License API namespace，共 3 个 form-encoded `POST` operation；
- Webhook management 属于 Authenticated JSON:API，inbound delivery 则是服务端向消费者发送的另一条协议边界。

换算到已经冻结的 Explicit Client 命名：v4 能力对应 20 个 namespace / 59 个方法；加入 Affiliates 的 `get`、`list` 后，v5 当前候选全集是 **21 个 namespace / 61 个方法**。61 比官方 endpoint operation 多 1，是因为 `customers.archive` 是对官方 Customer `PATCH` 的稳定 convenience，不是额外 endpoint。

官方 JavaScript SDK `v4.0.0` 已实现除 Affiliates 外的 19 个 Authenticated resources、55 个 endpoint operation，并实现全部 3 个 License API operation，另有 `archiveCustomer` convenience。这里的“实现”只表示存在对应调用函数，不表示其类型、序列化或 transport 行为完全正确。可确认的 operation 级缺口是 Affiliates 的 `get`/`list`；已实现但签名不完整的 operation 是两个 refund（官方 `amount` 可省略以发起全额退款，v4 要求 `amount`）。此外，2025/2026 新增 response fields、relationships 和 webhook events 会扩大既有模块的类型覆盖。

来源：[API Reference 导航与协议说明](https://docs.lemonsqueezy.com/api)、[API Changelog](https://docs.lemonsqueezy.com/api/getting-started/changelog)、[官方 JavaScript SDK v4.0.0](https://github.com/lmsqueezy/lemonsqueezy.js/tree/v4.0.0/src)。

## 方法与标记

1. operation 集合以官方 [API Reference](https://docs.lemonsqueezy.com/api) 当前导航及每个 endpoint 页为准。
2. v4 覆盖以官方 SDK [`v4.0.0`](https://github.com/lmsqueezy/lemonsqueezy.js/releases/tag/v4.0.0) 的 `src` 导出和函数实现为准。
3. `完整`：v4 有对应 method/path；`部分`：有对应 operation，但公开签名不能表达当前官方行为；`无`：v4 没有对应模块或函数。
4. “未发现”仅表示截至截止日在上述公开一手资料中没有找到，不证明服务端不存在未公开能力。
5. “v5 beta 缺口”是相对当前官方 API 和已确认契约的事实差，不是本研究替项目决定首发范围。

## License API：独立的三个 operation

License API 明确是与 Authenticated API 分离的 API：不使用 Bearer credential；`POST` 为 `application/x-www-form-urlencoded`，`Accept` 为 `application/json`，响应不是 JSON:API envelope，独立 rate limit 为每分钟 60 次。来源：[License API](https://docs.lemonsqueezy.com/api/license-api)。

| v5 `license` method | Method + path               | 输入                                           | 业务结果 discriminator                                       | v4 覆盖                   | 直接来源                                                                                                                                                                       |
| ------------------- | --------------------------- | ---------------------------------------------- | ------------------------------------------------------------ | ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `activate`          | `POST /licenses/activate`   | required `license_key`, `instance_name`        | `activated: boolean`；业务失败可在 JSON body 的 `error` 表达 | 完整：`activateLicense`   | [Activate](https://docs.lemonsqueezy.com/api/license-api/activate-license-key), [v4 source](https://github.com/lmsqueezy/lemonsqueezy.js/blob/v4.0.0/src/license/index.ts)     |
| `validate`          | `POST /licenses/validate`   | required `license_key`; optional `instance_id` | `valid: boolean`；不带 instance 时 `instance: null`          | 完整：`validateLicense`   | [Validate](https://docs.lemonsqueezy.com/api/license-api/validate-license-key), [v4 source](https://github.com/lmsqueezy/lemonsqueezy.js/blob/v4.0.0/src/license/index.ts)     |

因此，HTTP `200` 搭配 `valid: false`、`activated: false` 或 body `error` 不能被 transport 自动误判为 HTTP failure；这是 License API 的业务响应语义。

## Webhooks：management 与 inbound delivery 两条边界

### Management resource

Authenticated Webhooks API 完整提供 create/get/update/delete/list；delete 成功明确为 `204 No Content`。create 要求 `url`、`events`、`secret`，`test_mode` 可选，并关联 store；`secret` 不会出现在 response。来源：[Webhook object](https://docs.lemonsqueezy.com/api/webhooks/the-webhook-object)、[Create](https://docs.lemonsqueezy.com/api/webhooks/create-webhook)、[Delete](https://docs.lemonsqueezy.com/api/webhooks/delete-webhook)。

官方 List 页面称返回分页列表，但页面当前 JSON 示例把 `data` 写成单对象。由于 endpoint prose 和分页语义一致，单对象示例应记录为官方文档冲突，不能据此把 list 建模成单项；若需要进一步确认，只能用官方澄清或 sanitized Test Mode observation 扩充证据。[List Webhooks](https://docs.lemonsqueezy.com/api/webhooks/list-all-webhooks)

### Inbound delivery

Inbound delivery 不属于上述 57 个 client-to-API operation。官方协议为：

- Lemon Squeezy 对配置 URL 发送 `POST`；body 是带 `meta` 的 event-specific JSON:API resource；
- headers 包括 `Content-Type: application/json`、`X-Event-Name`、`X-Signature`；
- `X-Signature` 是以 signing secret 对原始 body 计算的 HMAC-SHA256 hex digest；
- 官方要求精确 `200` 表示接收成功，其他状态最多再重试 3 次，示例退避为 5、25、125 秒；
- checkout custom data 仅明确保证在 Order、Subscription、License Key 相关事件的 `meta.custom_data` 中。

来源：[Webhook Requests](https://docs.lemonsqueezy.com/help/webhooks/webhook-requests)、[Signing Requests](https://docs.lemonsqueezy.com/help/webhooks/signing-requests)。

官方 [Event Types](https://docs.lemonsqueezy.com/help/webhooks/event-types) 自称完整列表，截至截止日共 17 个：

| Payload resource     | Event names                                                                                                                                                              |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Order                | `order_created`, `order_refunded`                                                                                                                                        |
| Customer             | `customer_updated`                                                                                                                                                       |
| Subscription         | `subscription_created`, `subscription_updated`, `subscription_cancelled`, `subscription_resumed`, `subscription_expired`, `subscription_paused`, `subscription_unpaused` |
| Subscription Invoice | `subscription_payment_success`, `subscription_payment_failed`, `subscription_payment_recovered`, `subscription_payment_refunded`                                         |
| License Key          | `license_key_created`, `license_key_updated`                                                                                                                             |
| Affiliate            | `affiliate_activated`                                                                                                                                                    |

v4 的 event union 没有 `affiliate_activated` 和 `customer_updated`，其余 15 项已列出：[v4 Webhook types](https://github.com/lmsqueezy/lemonsqueezy.js/blob/v4.0.0/src/webhooks/types.ts)。专门的 Event Types 页面仍列出 `subscription_payment_refunded`，不能因为简版 Developer Guide 遗漏它而移除。

官方没有在 webhook request/signing 页面公开 delivery ID、事件 timestamp、签名 timestamp 或 replay-tolerance 协议，不能推断存在类似 Stripe 的 replay window。官方模拟页列出的 `subscription_plan_changed` 不在“完整事件列表”和 changelog 中；目前不能确认它是可订阅的正式 inbound event。[Simulate Webhook Events](https://docs.lemonsqueezy.com/help/webhooks/simulate-webhook-events)

## 未发现与仍需保留的不确定性

- 未发现当前导航之外的 Authenticated API resource 或 operation；这只是公开文档结论。
- 未发现 Affiliates write endpoint、Order/Subscription Invoice 的 `affiliate_id` list filter，或通用任意 URL operation。
- 未发现 2025/2026 删除 endpoint、改变 HTTP method、推出 `/v2`、缩窄 enum 或新增 deprecation 的官方记录。
- Webhook Update 示例与字段说明对 `store_id` 是否可写并不一致；不能仅凭示例把 store relocation 建模为支持的 update input。[Update Webhook](https://docs.lemonsqueezy.com/api/webhooks/update-webhook)
- Subscription URL 字段在 prose/changelog 的 `update_customer_portal` 与 JSON 示例的 `customer_portal_update_subscription` 之间冲突；这属于 response 类型证据冲突，不是 operation 范围变化。[Subscription object](https://docs.lemonsqueezy.com/api/subscriptions/the-subscription-object)、[Changelog](https://docs.lemonsqueezy.com/api/getting-started/changelog)
- 当前官方公开资料未提供 OpenAPI/JSON Schema 等机器可读 truth source；operation coverage 仍需以人工审核的官方导航、endpoint prose 和 changelog 维护。[官方 GitHub organization repositories](https://github.com/orgs/lmsqueezy/repositories)

## 供范围决策使用的事实清单（不替代决策）

1. 若目标是与当前公开 API operation 等价，Explicit Client 候选全集是 21 个 namespaces / 61 个 methods；其底层是 Authenticated API 20 resources / 57 endpoints、License API 3 endpoints，以及 1 个无新增 endpoint 的 `customers.archive` convenience。
2. v4 对应 20 个 namespaces / 59 个 methods；仅缺 Affiliate 的 2 个 methods。两个 refund 已存在但参数需要从必填改为可选以覆盖全额退款。
3. “完整 operation 覆盖”不等于“所有资源 CRUD”：官方多数 resources 本来就是只读，不能补造 write methods。
4. Webhook management 是 5 个普通 Authenticated operations；inbound receiver 是另一个协议模块，不应被统计成第 58 个 operation。
5. 2025/2026 drift 主要是一个只读 resource、两个 event 和既有资源字段/relationship 扩展，不需要新建其他 API resources。
